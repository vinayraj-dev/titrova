      Salesforce order of execution, step by step

      Every time a record is saved, Salesforce runs its automation in a fixed sequence. Knowing that sequence explains most “why did this field change?” bugs. These are the steps Org X-ray replays, simplified from Salesforce’s documentation.

      When a record is created or updated

      1. Original record loaded

        Salesforce loads the existing record from the database, or initializes a new record for an insert.

      2. New values and system validation

        New field values overwrite the old ones. For saves from the user interface, Salesforce checks layout-required fields, field formats and maximum lengths. For API saves, it checks foreign keys and restricted picklists.

      3. Before-save flows

        Record-triggered flows set to run before the record is saved. They update fields on the same record without extra DML, and they run before any Apex.

      4. Before triggers

        Apex before triggers run. A value a before trigger sets replaces any value a before-save flow set on the same field.

      5. Validation rules

        Most system validation runs again, including required fields, then your custom validation rules. If any rule fails, the save stops and nothing after this runs.

      6. Duplicate rules

        Duplicate rules look for matching records. A rule can block the save or let it through with an alert.

      7. Record saved, not committed

        The record is written to the database, but the transaction is not committed yet. A new record now has an Id.

      8. After triggers

        Apex after triggers run. They can read the saved record, including its Id, and change related records.

      9. Assignment rules

        Assignment rules route Leads and Cases to an owner or queue.

      10. Auto-response rules

        Auto-response rules send automatic emails for Leads and Cases.

      11. Workflow rules

        Legacy workflow rules evaluate. If a rule’s field update changes the record, the record is saved again.

      12. Update triggers run again

        Because a workflow field update changed the record, before update and after update triggers fire one more time. Validation rules, flows and duplicate rules do not run again.

      13. Escalation rules

        Case escalation rules evaluate.

      14. Processes

        Legacy Process Builder processes run. Their order relative to each other is not guaranteed.

      15. After-save flows

        Record-triggered flows set to run after the record is saved, in trigger order. If a flow updates the record that triggered it, the record is saved again and the sequence repeats.

      16. Entitlement rules

        Entitlement rules evaluate for records that use entitlement processes.

      17. Roll-up summaries and parents

        Roll-up summary fields recalculate on parent records. Each parent then goes through its own save, with its own automation, and grandparents follow the same way.

      18. Criteria-based sharing

        Criteria-based sharing rules are evaluated.

      19. Commit

        All changes in the transaction are committed to the database together.

      20. After commit

        Salesforce sends emails and starts queued asynchronous work: queueable and future Apex, platform events, and asynchronous paths in record-triggered flows.

      When a record is deleted

      1. Record loaded

        Salesforce loads the record that is being deleted.

      2. Before-delete flows and before delete triggers

        Record-triggered flows set to run before delete, and Apex before delete triggers. Don’t build logic that depends on one of these running before the other.

      3. Record deleted, not committed

        The record moves to the Recycle Bin inside the open transaction. Validation rules don’t run when a record is deleted.

      4. After delete triggers

        Apex after delete triggers run.

      5. Roll-up summaries and parents

        Parent roll-up summary fields recalculate, and each parent goes through its own save.

      6. Commit

        All changes in the transaction are committed to the database together.

      7. After commit

        Queued asynchronous work starts, such as queueable and future Apex.

      Within a single step, Salesforce doesn’t guarantee the order of multiple Apex triggers on the same object and event, or of multiple processes. Record-triggered flows follow their trigger order: 1 to 1000 first, then flows with no trigger order, then 1001 to 2000. Flows with the same trigger order run in alphabetical order of their API names.

      What Org X-ray checks

      • Fields written by more than one automation, and which one wins.
      • Before-save flow values replaced by Apex before triggers.
      • Workflow field updates that make update triggers run a second time.
      • After-save flows and processes that update their own record and restart the save.
      • More than one Apex trigger on the same object.
      • Record-triggered flows without an explicit trigger order.
      • SOQL queries and DML statements inside loops.
      • Apex classes declared without sharing.
      • Dynamic SOQL built by joining strings, which can allow SOQL injection.
      • Hardcoded record IDs in Apex.
      • Legacy workflow rules and processes that should move to flows.

      Frequently asked questions

      What is the Salesforce order of execution?

      It is the fixed sequence Salesforce follows when a record is saved: system validation, before-save flows, before triggers, validation rules, duplicate rules, the save itself, after triggers, assignment and auto-response rules, workflow rules, processes, after-save flows, roll-up summaries, sharing, commit, and finally post-commit work such as emails and asynchronous Apex.

      Is my Salesforce metadata uploaded anywhere?

      No. Org X-ray reads your zip file inside your own browser with JavaScript. Nothing is uploaded, stored or sent to any server, so you can safely use it on client orgs.

      Why does my before-save flow value get overwritten?

      Before-save flows run before Apex before triggers. If a trigger sets the same field, the trigger’s value replaces the flow’s value. Org X-ray marks these fields as conflicts and shows which automation wins.

      Which metadata types does Org X-ray read?

      Apex triggers and classes, record-triggered flows, Process Builder processes, workflow rules and field updates, validation rules, roll-up summary fields, duplicate rules, and assignment, auto-response and escalation rules, in both Metadata API and Salesforce DX source format.

      In what order do multiple record-triggered flows run?

      Flows with a trigger order from 1 to 1000 run first, in that order. Flows with no trigger order run next, then flows with a trigger order from 1001 to 2000. Flows with the same trigger order run in alphabetical order of their API names.
